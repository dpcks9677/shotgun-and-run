## 1. 목표

- 지금의 3/4 시점 3D 파티클 폭발(CFXR)을 **탑다운 시점에 맞는 폭발**로 바꾼다.
- 폭발은 **원형 범위**로 일어난다. 눈에 보이는 불덩이의 바깥 끝이 실제 피해 반경(`_radius` 2.5u)과 맞아야 한다.
- 폭발 뒤에 **흙먼지가 잔상으로 남는다**. 불이 꺼진 뒤에도 먼지 구름이 한동안 떠 있다가 흩어진다.
- 레퍼런스 두 장(용암 같은 툰 폭발)의 **형태 · 색 구성**을 따르되, 위에서 내려다본 모습으로 다시 그린다.

**제외:** 폭발음, 화면 흔들림, 피해 · 판정 로직 변경, 섬광탄의 플레이어 화면 백색 플래시 · 적 기절 로직(9.6).

## 2. 현재 상태 (조사 결과)

### 2.1 폭발이 일어나는 흐름

- `FragmentGrenade` ([FragmentGrenade.cs](../Assets/02.Scripts/Consumable/Combat/FragmentGrenade.cs)): `Start`에서 범위 원을 켜고 → `_countdown`(프리팹 값 2초) 뒤 `Explosion.FindTargetsInExplosion(_radius)`로 `OverlapCircleAll` → 피해 → `Instantiate(_vfx, transform.position, transform.rotation)` → 범위 원 숨김 → 수류탄 `Destroy`.
- 프리팹 `FragmentGrenade.prefab`: `_radius` 2.5 · `_damage` 250 · `_vfx` = **`CFXR Explosion 3 Bigger`** (JMO Cartoon FX Remaster).
- 수류탄이 자기 자신을 파괴하므로 **VFX는 자기 수명을 스스로 관리**해야 한다 (CFXR은 자체 자동 파괴를 쓴다).
- 범위 표시는 `ExplosionRangeIndicator`(LineRenderer 원 64분할, 빨강)와 조준 중 미리보기 `ExplosionIndicator`가 맡는다. 이번에 건드리지 않는다.

### 2.2 지금 폭발이 탑다운에 안 맞는 이유

- CFXR 폭발은 **옆에서 본 3D 불덩이**(위로 솟는 구름 + 파편 + 연기)다. 레퍼런스와 같은 계열이라 탑다운 평면에서는 "위로 솟는" 움직임이 의미 없이 겹쳐 보이고, **반경 2.5u 원과 모양이 맞지 않는다**.
- 흙먼지 잔상이 없다 (연기는 위로 올라가며 사라짐).

### 2.3 이 프로젝트의 연출 관례 (그대로 따를 것)

| 항목 | 관례 | 근거 |

### 2.4 렌더링 조건

- 2D Renderer(URP 17.3) + Global Light 2D 0.5로 던전이 어둡다. **2D 라이트를 받는 머티리얼로 불꽃을 그리면 안 보이므로** 불꽃 · 불씨는 가산(스스로 빛남), 먼지는 아래 4.4 방식으로 처리한다.
- 정렬 레이어(아래 → 위): … Blood · Afterimage · Characters · Weapon · Bullet · **Grenade** · Foreground · UI.
- 카메라 흔들림 · Cinemachine은 프로젝트에 없다.

## 3. 결정 사항

### 3.1 그림체 — **A안 도트로 확정**

레퍼런스는 **매끈한 툰 셰이딩**이고, 이 프로젝트는 **PPU 16 도트**다. 둘을 섞으면 폭발만 이질적으로 보인다.

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 도트 (추천)** | 형태 · 색 구성은 레퍼런스를 따르되 도트 프레임 애니로 그림. 기존 툴킷 그대로 | 던전 · 펠릿 연출과 룩이 같음. 임포트 규칙 · 검사 도구 재사용 | 레퍼런스의 매끈한 용암 질감은 포기 (도트로 셀 셰이딩 근사) |
| B. 매끈한 툰 | 고해상도 소프트 텍스처 + `ParticleSystem` (CFXR 텍스처 `fire circle` · `smoke dissolve` 재활용 가능) | 레퍼런스에 가장 가까움 | 도트 던전 위에서 해상도 불일치. 텍스처 · 머티리얼 관례를 새로 만들어야 함 |

→ 이 계획서는 **A안**을 기준으로 쓴다. B안을 고르면 4.2 · 4.3의 "프레임 시트"가 "파티클 텍스처"로 바뀌고 나머지 구조는 같다.

### 3.2 구성 방식

- **그림체 규칙 (v05)**: 기존 작업본(펠릿 연출 · DashDust · 존 소품)과 맞춘다 — 불꽃은 `pellet_vfx.py` 팔레트(`FL_R · FL_O · FL_Y · FL_W`), 색은 3~4톤 평면 명암(노이즈 · 그라데이션 없음), 불투명 도트, 파티클은 배율이 아니라 프레임 교체로 크기를 바꾼다.
- **바닥 섬광은 유지, 8갈래 별(충격 줄기)은 삭제 (v06 요청)**: 첫 순간 번쩍(`FlashCore`) · 바닥 빛 웅덩이(임시 `Light2D`) · 바닥 충격 링은 둔다. 베이지 칼날 8줄기(`ShockRays`)는 만들지 않는다. (v05에서 "바닥 섬광"을 이 별로 읽어야 했는데 빛 · 링을 지웠다가 되돌림)

- **불덩이 · 충격 링 · 첫 번쩍 = 스프라이트 프레임 애니** (모양을 직접 통제해야 하는 부분)
- **흙먼지 · 불씨 = `ParticleSystem`** (수가 많고 무작위여야 하는 부분)
- **하나의 프리팹 `GrenadeExplosion`** 에 모두 담고, 루트의 스크립트 하나가 반경 스케일 · 수명 · 정리를 맡는다.

### 3.3 시각 반경 = 판정 반경 · 시점

- **시점 (v02 피드백 → v08 갱신)**: 순수 수직 탑다운이 아니라 **비스듬한 시점**으로 그린다. 처음에는 범위 원이 진짜 원이라 바닥 요소를 원으로 두었으나, dev의 `69516cce`(투척 소모품 폭발 범위를 **타원**으로 표시, `ExplosionRangeIndicator._verticalScale` 기본 0.65)를 PM에 적용하면서 **바닥에 닿는 요소(충격 링 · 그을음 · 섬광 도넛)도 같은 세로 0.65배 타원**으로 바꿨다 (`grenade_vfx.py`의 `GROUND_V`, 도트가 늘어나지 않도록 프리팹 스케일이 아니라 시트에 구워 둠 — 인디케이터 값을 바꾸면 이 값도 맞춰 시트를 다시 만들 것). **불덩이 · 먼지 · 불씨는 높이를 가진 입체로 위(화면 위쪽)로 솟는다.** 불덩이 윗부분은 R보다 위로 나오고 바닥 쪽은 타원 안에서 끝난다. 바닥 빛(`Light2D`)은 원형 그대로다.

- 불덩이 바닥 쪽 최대 확장 · 충격 링 끝 · 먼지 분포 반경이 모두 `_radius`에 맞는다.
- 스프라이트는 기준 반경 **2.5u(= 40px 반경, 지름 80px)** 로 그리고, 수류탄이 `Play(radius)`로 반경을 넘기면 루트 스케일을 `radius / 기준 반경`으로 맞춘다. 기준 반경은 프리팹마다 다르므로(파편 2.5u · 섬광 4u) `GrenadeExplosionVFX`의 인스펙터 필드로 둔다. 반경을 기획에서 바꿔도 (아이템 설명 · 프리팹 값) VFX가 따라간다.
- 파티클은 스케일이 속도 · 크기에 반영되도록 `scalingMode = Hierarchy`.

### 3.4 범위 밖

- 섬광탄은 9절에서 함께 교체한다. 교체가 끝나면 `CFXR Flash`도 참조가 없어질 수 있으나, CFXR 폴더 정리는 두 연출 모두 확정된 뒤 별도로 판단한다 (지금은 지우지 않는다).
- 폭발음 · 화면 흔들림 · 피해 로직은 건드리지 않는다.

## 4. 연출 설계 (탑다운, 기준 반경 R = 2.5u)

### 4.1 타임라인

| 시간(초) | 요소 | 동작 |
|---|---|---|
| 0.00 | 첫 번쩍 + 바닥 빛 | 흰 핵 + 노랑 · 주황 테가 한 프레임에 번쩍(가산, 0.09초 안에 사라짐). 동시에 임시 `Light2D` 점광 (주황, 반경 약 1.5R, 0.45초 감쇠) — 어두운 홀 · 방 바닥이 순간 밝아짐 |

| 0.05~0.35 | **충격 링** | 바닥에 얇은 밝은 고리가 R까지 퍼지고 사라짐(가산). 판정 범위의 끝을 짚어 줌 |
| 0.05~0.70 | **불씨** | 점 파티클 24개 이내. 사방으로 튀며 감속, 주황 → 붉은색 → 소멸 |
| 0.15~1.15 | **흙먼지 잔상** | **0.15초부터**(불덩이가 식기 직전) 나온다 (v02 피드백: 폭발 처음부터 먼지가 섞이면 폭발감이 죽는다 → v07: 인게임에서 늦어 보여 0.28초에서 앞당김). 구름 파티클 12개가 덩어리 안(반경 1.25u)에서 생성돼 **위로 떠오르며** 천천히 번지고 알파가 빠진다. 파티클 수명 0.7초, 생성 시각이 0.25초 퍼져 전체 약 1초 동안 보임. 크기는 최대 0.66배(약 32×20px, v07: 불덩이에 비해 너무 컸음). 알파 상한 0.5. 처음 0.35초는 붉은 기운 → 회색 |
| 0.05~8.30 | 그을음 | 폭발 직후 나타나 8초에 걸쳐 사라짐 |

먼지 잔상은 약 1.1초에 끝나고, 그을음이 마지막 요소로 약 8.3초까지 남는다. 수류탄은 최대 3개 쌓이므로 동시에 폭발해도 파티클은 100개 미만이다. 풀링은 쓰지 않는다 (`Instantiate`/`Destroy`로 충분, 현재 방식 유지).

- 회전 · 좌우 반전으로 같은 모양이 반복돼 보이지 않게 한다 (불덩이는 좌우 반전만).

### 4.3 Unity 구성 (프리팹 `GrenadeExplosion`)

```
GrenadeExplosion          ← GrenadeExplosionVFX (신규 스크립트)
├─ Fireball               SpriteRenderer, Unlit, 프레임 재생, Grenade 레이어 order +2
├─ Flash                  SpriteRenderer, 가산, Grenade 레이어 order +3
├─ ShockRing              SpriteRenderer, 가산, 바닥 쪽 정렬 (4.6)
├─ Embers                 ParticleSystem, 가산, Grenade 레이어 order +4
├─ Dust                   ParticleSystem, Unlit(어두운 회색), 4.4 참고
├─ Scorch                 SpriteRenderer, 바닥 쪽 정렬 (4.6)
└─ Light                  Light2D (Point), 감쇠 스크립트
```

- 위치: `Assets/09.VFX/Consumable/Grenade/` (PNG · 머티리얼 · 프리팹). 펠릿 연출이 `Assets/09.VFX/Weapon/Pellet/`에 있는 것과 같은 구조.
- 가산 머티리얼은 기존 `ShotgunAndRun/Sprite Additive`를 쓴다. 새 셰이더는 만들지 않는다.
- 재생 스크립트 `GrenadeExplosionVFX` (`Assets/02.Scripts/Consumable/Presentation/`, 네임스페이스 `Consumable`):
  - `Play(float radius)`: 스케일 설정 → 프레임 재생 시작 → 파티클 재생.
  - 프레임 재생은 `PelletImpact`의 방식(타이머로 프레임 인덱스, 위치 1px 스냅)을 따르되 여러 렌더러를 한 타임라인으로 묶는다.
  - 마지막 요소(그을음 페이드, 약 8.3초)가 끝나면 `Destroy(gameObject)`.
  - 프레임 · 프레임레이트 · 지속 시간은 인스펙터 필드로 노출하지만 불필요한 "설정 가능성"은 만들지 않는다.

### 4.4 흙먼지 (잔상) 처리

- **어두운 던전에서 보여야 한다**: `Sprite-Lit`로 그리면 Global Light 0.5 아래에서 거의 안 보인다. 먼지는 `Sprite-Unlit-Default`에 짙은 회색~회갈색(`DUST (132,126,116)` · `DUST_DK (92,88,82)`를 `pellet_vfx.py`에서 재사용)으로 두고, **수명 그라디언트로 알파를 0.55 → 0**으로 뺀다.
- 폭발 직후에는 불빛을 받은 듯 **붉은 기운**(0.3초), 이후 회색으로 식는다. 이 색 변화로 "불빛이 꺼진 뒤 남은 먼지"를 표현한다.
- 플레이어가 먼지 속에 있어도 가리지 않도록 알파 상한을 낮게 잡고(0.55) 정렬은 `Grenade` 레이어(Characters 위, Foreground 아래)로 둔다. 시야 방해가 심하면 상한을 더 낮춘다 (검증 항목 5.3).

### 4.5 그을음 데칼 (확정: 포함)

- 폭발 지점에 R보다 약간 작은 어두운 얼룩이 남아 8초에 걸쳐 사라진다. 바닥 위에 "남는 흔적"이라는 느낌을 더해 준다.
- 영구 데칼은 제안하지 않는다 (방 청소 시점 · 성능 · 타일맵 위 정렬 문제가 생김).

### 4.6 정렬 (바닥 / 공중)

- 탑다운에서 **충격 링 · 그을음은 바닥**에 붙은 것, **불덩이 · 먼지 · 불씨는 바닥 위**에 뜬 것이다.
- 바닥 쪽은 `Blood` 레이어 위(order +), 공중 쪽은 `Grenade` 레이어로 한다. 이렇게 하면 플레이어 · 적은 줄기 위에 서 있고 불덩이 · 먼지는 그 위를 덮는다.

## 7. 검증

1. **반경 일치**: 플레이 모드에서 범위 원(LineRenderer)과 폭발 불덩이 최대 외곽이 겹치는지. 반경 값을 2.5 → 4로 바꿨을 때 VFX도 같은 비율로 커지는지.
2. **어두운 곳 가독성**: 어두운 홀 · 방 바닥에서 불덩이 · 먼지가 보이는지, 밝은 방에서는 과하지 않은지.
3. **먼지가 시야를 가리지 않는지**: 플레이어 · 적이 먼지 속에 있을 때 식별 가능한지. 알파 상한 조정.
4. **동시 폭발**: 수류탄 3개를 겹쳐 던졌을 때 프레임 드롭 · 정렬 깨짐이 없는지.
5. **정리**: 잔상이 끝난 뒤 `GrenadeExplosion` 오브젝트와 임시 `Light2D`가 남지 않는지(하이어라키 확인). 폭발 도중 씬을 나가도 오류가 없는지.
6. **회귀**: 피해 · 판정 결과가 이전과 같은지(코드 변경이 VFX 생성 직후 한 곳뿐). 섬광탄은 9.5 검증으로 따로 본다.
7. 열린 씬에 임시 오브젝트를 만들어 테스트할 때는 `try/finally`로 정리한다 (씬 오염 방지).

## 9. 섬광탄 폭발 연출 (추가: 2026-10-08)

### 9.1 현재 상태

- `FlashBang` ([FlashBang.cs](../Assets/02.Scripts/Consumable/Combat/FlashBang.cs))는 파편 수류탄과 같은 구조다: `_countdown`(프리팹 1초) → `OverlapCircleAll(_radius)` → 적 기절(`TODO`, 아직 미구현) → `Instantiate(_vfx, transform.position, transform.rotation)` → 수류탄 `Destroy`.
- 프리팹 `FlashBang.prefab`: `_radius` **4** · `_stunTime` 2 · `_countdown` 1 · `_vfx` = **`CFXR Flash`**. 이 값은 이번에 바꾸지 않는다. (파편 수류탄은 2초로 확정했지만 섬광탄은 기획 문서에 시간이 없고 둘의 값이 다른 것이 의도일 수 있어 그대로 둔다.)
- 레퍼런스(첨부): 중심에서 여러 가닥의 가는 광선이 뻗는 **금빛 별 섬광**. 중앙은 작고 밝은 핵, 광선 끝으로 갈수록 가늘고 투명해진다.

### 9.2 요구 사항 → 설계

| 요구 | 설계 |
|---|---|
| 도넛이 중심에서 범위 끝까지 커짐 | **`Ring`**: 속이 빈 두꺼운 도넛이 중심에서 시작해 **반경 R = 4u(64px)** 에서 멈춘다. 퍼질수록 두께가 얇아지고 알파가 빠진다 (두꺼움 → 얇음으로 도넛이 "펼쳐지는" 느낌). 마지막 프레임의 바깥 가장자리 = 판정 반경 |
| 빛나는 십자 모양 섬광이 중앙 | **`Cross`**: 중앙의 **4방향(상하좌우) 주 광선** + 레퍼런스처럼 짧은 **대각선 보조 광선 4줄**(더 가늘고 어둡게). 끝으로 갈수록 가늘어지는 광선. 회전하지 않는다 (십자는 축에 맞아야 도트가 깔끔) |
| 너무 하얗지 않게, 노랑과 혼합 | 순백은 **중앙 핵 3~5px**에만 쓰고, 나머지는 노랑 → 황금색. 광선 · 도넛은 `(255,235,140)` → `(255,205,60)` → `(230,155,20)` |

- 순백 사용 규칙(검사 항목): 프레임 전체에서 `(255,255,255)` 픽셀은 중앙 반경 3px 밖에 없어야 한다. 가산 블렌딩이라 겹치면 흰색으로 날아가므로, 광선 · 도넛 알파 상한을 0.8로 두고 겹치는 구간은 색을 한 단계 어둡게 그린다.
- 파편 폭발과 구분: 파편은 주황 · 갈색 · 먼지, 섬광은 **금빛 · 가볍고 차가운 번쩍임**. 먼지 · 그을음 · 충격 줄기는 없다.

### 9.3 타임라인 (기준 반경 R = 4u)

| 시간(초) | 요소 | 동작 |
|---|---|---|
| 0.00 | 핵 + 십자 | 첫 프레임에 중앙 핵이 번쩍하고 십자 광선이 바로 가장 길어짐(최대 약 0.8R) |
| 0.00~0.35 | **도넛 링** | 중심 → R까지 확장, 두께 감소 · 알파 감소. 8프레임 @ 24fps. ease-out (처음 빠르고 끝에서 느려짐) |
| 0.05~0.40 | 십자 | 광선이 서서히 짧아지고 어두워지며 핵이 작아짐. 6~7프레임 |
| 0.00~0.35 | 임시 `Light2D` | 노랑 `(255,225,120)`, 반경 약 1.2R, 세기 1.2 → 0 감쇠. 어두운 방에서 바닥이 번쩍 밝아짐. 세기는 눈부심을 줄이려고 파편(주황)보다 낮게 |
| 0.10~0.60 | 잔광 | 노란 점 파티클 12개 이내, 느리게 흩날리다 사라짐. 텍스처는 `GrenadeSpark.png`(3×3) 재사용 + 노랑 틴트 |

총 지속 약 0.6초. 먼지 · 그을음이 없어 풀링 · 후처리도 필요 없다.

### 9.5 검증

1. **반경 일치**: 도넛의 바깥 가장자리가 범위 원(4u)에 맞게 끝나는지.
2. **눈부심**: 밝은 방 · 어두운 방 모두에서 화면이 하얗게 날아가지 않는지. 겹치는 구간 순백 픽셀이 중앙 핵 밖에 없는지(검사 스크립트).
3. 도넛이 속이 빈 채로 커지는지 (가운데가 채워져 보이지 않는지).
4. 십자 광선이 4방향 · 대각선으로 읽히는지, 레퍼런스처럼 끝이 가늘어지는지 — **확대해서 직접 본다**.
