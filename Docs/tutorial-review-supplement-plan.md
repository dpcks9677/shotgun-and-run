# 튜토리얼 씬 보충안 작업 계획서

작성일: 2026-10-09 · 상태: **A단계 · B단계(코드만 가능한 항목) 구현 완료. 씬 수정이 필요한 B1과 결정이 필요한 A6 · BGM은 보류** · 대상: `TutorialMapScene` · `Assets/_Sandbox/Yechann/Tutorial` · `Assets/_Sandbox/Yechann/Cutscene`

검수에서 나온 항목 11개를 어떻게 고칠지 정리한다. 코드 · 데이터 · 대본 대조 결과이며 화면 연출과 음향은 직접 확인하지 못했다(편집기가 포커스를 잃으면 프레임이 멈춰 캡처가 불가능했다). 구현 후 플레이 확인이 필요하다.

## 1. 작업 묶음과 순서

| 단계 | 내용 | 항목 | 씬 파일 수정 |
|---|---|---|---|
| A | 흐름 안정화 (막힘 해소) | A1~A5 | 없음 |
| B | 연출 보강 | B1~B7 | B1 · B7 일부만 |
| C | 문서 · 디버거 동기화, 검증 | C1~C3 | 없음 |

A를 먼저 끝내고 확인한 뒤 B로 간다. A는 코드만 고치므로 씬 파일 충돌이 없다.

## 2. A단계: 흐름 안정화

### A1. 구역 감지를 "한 번이라도 들어왔는지"로 바꾼다
- 문제: `WaitZone`이 `PlayerInside`(지금 안에 있는지)만 본다. 빨리 지나가면 단계가 안 열린다.
- 변경:
  - `TutorialZone`에 `HasEntered`(들어온 적 있음)와 `ResetEntered()`를 추가한다.
  - `TutorialFlow.WaitZone`은 `HasEntered`를 기다린다. 각 단계가 시작될 때 해당 구역의 기록을 지워, 앞 단계에서 지나친 구역이 곧바로 통과되지 않게 한다.
  - 디버그 상태 적용(`ApplyStageState`)은 모든 구역의 기록을 지운다.
- 알려진 절충: 단계가 시작되기 전에 이미 지나간 구역은 기록이 지워지므로 다시 들어가야 한다. 각 구역이 서로 멀어 실제로는 걸리지 않는다.

### A2. 상자 안내를 진행에서 분리한다
- 문제: `LootGuide`가 상자를 열고 비울 때까지 기다리고 그 뒤에야 보라 방 컷씬 단계가 시작된다. 상자를 건너뛰면 적이 얼어붙은 채 컷씬도 전투도 일어나지 않고, 팝업은 구역을 벗어나도 남는다. 대본(§3-5)은 "안 열어도 지나갈 수 있고, 팝업은 접근할 때만 뜬다"이다.
- 변경:
  - `LootGuide`를 단계 목록에서 빼고 "보조 안내"로 바꿔 `ChestSpot` 컷씬이 끝나면 병행 코루틴으로 시작한다.
  - 보조 안내는 플레이어가 `Loot` 구역 안에 있고 상자를 아직 안 열었을 때 "E 키를 길게 눌러 상자 열기", 열었고 내용물이 남았을 때 "아이템을 더블 클릭해 인벤토리에 담기"를 띄우고, 구역을 벗어나면 숨긴다.
  - 보라 방 입구 구역에 들어오면(`ArenaIntro` 단계 시작) 보조 안내를 끝내고 팝업을 닫는다.
  - 보조 안내 코루틴도 `StopFlow`가 멈추고 구독을 해제한다.
- 효과: 상자를 안 열고 지나가도 보라 방으로 정상 진행된다.

### A3. 샷건 줍기 안내를 넣는다
- 문제: "저게 뭐지?" 뒤에 E키 안내가 없다.
- 변경: `ShotgunPickup` 단계가 시작되면 팝업 "E 키로 샷건 줍기"(`_pickupGuide` 직렬화 문구)를 띄우고 줍는 순간 닫는다.
- 선택 사항: 줍기 범위에 들어오면 샷건이 깜빡이는 표시. 우선은 팝업만 한다.

### A4. 대시 안내를 진행 조건에서 뺀다
- 문제: 대시를 안 하면 샷건 컷씬이 열리지 않는다. 대본은 "대시를 해야만 지나는 지형은 두지 않는다"이다.
- 변경: 대시 안내를 A2와 같은 보조 안내로 바꾼다. 안내는 대시 구역에 들어오면 뜨고, 대시를 쓰거나 팔각방 입구 구역에 들어오면 닫는다. 샷건 컷씬은 대시와 무관하게 입구 구역 진입으로 시작한다.

### A5. 보조 안내 공통 틀
- A2 · A4가 쓰는 공통 틀 `StartSideGuide(IEnumerator)` / `StopSideGuide()`를 `TutorialFlow`에 둔다. 동시에 하나만 돌고, 새로 시작하면 이전 것을 멈추고 팝업을 닫는다.
- 디버그 재생의 `StopFlow`가 보조 안내도 멈추게 한다.

### A6. 튜토리얼 끝 → 다음 씬
- 현재: `_nextScene`이 비어 있어 검은 화면에서 멈춘다.
- 변경 방침: 쉘터 프롤로그 씬이 정해지면 `_nextScene`에 넣고 Build Settings에 등록한다. 지금은 이어질 씬이 없으므로 **결정이 필요하다**(§5 질문 1). 결정 전에는 비어 있을 때 콘솔 경고와 "다음 씬이 지정되지 않았습니다" 로그만 남긴다.

## 3. B단계: 연출 보강

### B1. 문 개방 연출
- 현재: 하늘색 전투가 끝나면 `_octagonGate.SetActive(false)`로 문이 갑자기 사라진다.
- 변경: `CS_TUTORIAL_SKY_CLEAR` 컷씬 앞부분에 문 개방 연출을 넣는다. 카메라가 문(`GateFocus` 마커)을 비추고, 작은 흔들림과 효과음(`_gateOpenSfx`)과 함께 문이 열리고, 카메라가 플레이어로 돌아와 기존 대사로 이어진다.
- 필요한 것: 문을 여는 신호(`OpenOctagonGate`)와 `GateFocus` 마커. 둘 다 **씬 파일에 추가**해야 한다. 그 전까지 `SetActive(false)`는 폴백으로 둔다.
- 디버그: SkyClear 시작 상태의 "문 열림"을 이 신호가 아니라 즉시 상태로 만든다(이미 `ApplyStageState`가 처리).

### B2. 사격 일시정지 시점
- 현재: 하늘색 컷씬이 끝나는 즉시 시간이 멈추고 "마우스 좌클릭으로 발사"가 뜬다. 대본은 "첫 적이 사거리 안에 들어오면"이다.
- 변경: 구현 중에 플레이어 위치에서 `SkyArrive`까지의 거리와 샷건 사거리를 비교한다. 이미 사거리 안이면 지금 방식을 유지하고 문구만 "마우스로 조준하고 좌클릭으로 발사"로 바꾼다. 사거리 밖이면 적을 푼 뒤 가장 가까운 적이 사거리 안에 들어올 때 정지한다.

### B3. 보라 전투 교착 방지
- 현재: 적이 정찰 상태라 못 찾으면 전투가 끝나지 않는다.
- 제약: `EnemyStateMachine.SetMode`는 `Begin` 이후 무시된다. 실행 중에 추격 모드로 바꾸려면 적 코드를 고쳐야 한다. 대본 §6은 "적 코드는 건드리지 않는다"이다.
- 변경: 적을 푼 뒤 일정 시간(기본 25초, 직렬화) 동안 전투 진행이 없으면 팝업 "남은 적을 모두 처치하세요 (n마리)"를 띄운다. 적 코드 수정은 하지 않는다.

### B4. 플레이어 시선 처리
- 컷씬에서 카메라가 대상을 비출 때 플레이어도 그쪽을 본다. `FaceTo(actor, marker)`가 이미 있다.
  - `ShotgunSpot` · `ShotgunGet`: `GunFocus` 쪽
  - `SkyIntro`: `SkyFocus` 쪽
  - `ArenaIntro`: `ArenaUpperFocus` → `ArenaLowerFocus` 쪽
  - `ChestSpot`: 복도 진행 방향(오른쪽). 상자 마커가 없어 `Face(left: false)`를 쓴다.
- 코드만 고치면 된다.

### B5. 적 반응
- 컷씬이 끝나 적이 풀릴 때 포효 효과음과 작은 카메라 흔들림을 넣는다(`_enemyAlertSfx`).
- 적 머리 위 경보 말풍선은 적이 `CutsceneActor`가 아니라서 지금 구조로 안 된다. 이번 범위에서는 제외하고 후속 과제로 둔다.

### B6. 오디오
- 추가할 효과음 자리(직렬화 `AudioClip`, 비워 두면 소리 없이 진행하는 기존 방식): 문 개방, 샷건 획득 시 장전음("철컥"), 적 경보, 기절 직전 이명 또는 심장박동.
- BGM: 컷씬 감독의 BGM 원본은 컷씬이 끝날 때마다 `Cleanup`에서 멈춘다. 튜토리얼 전체를 이어 가는 BGM은 별도 오디오 원본이 필요하고, 프로젝트에 공용 오디오 관리자는 없다. **결정이 필요하다**(§5 질문 2).
- 음원은 임시 음원 정책(대본 §1)을 따르고 기존 에셋을 재활용한다.

### B7. 레터박스
- `Letterbox(true)`를 `Escape` · `Faint*` · `Chase`의 시작에, `Letterbox(false)`를 끝에 넣는다. 컷씬 종료의 `ScreenFader.ResetAll`이 정리하므로 중단되어도 남지 않는다. 코드만 고치면 된다.

## 4. C단계: 문서 · 디버거 동기화, 검증

### C1. 디버거 반영
- 보조 안내와 구역 기록이 생기므로 `ApplyStageState`가 둘 다 초기화한다(위 A1 · A5).
- 이어서 진행(resume) 시 보조 안내가 필요한 단계에서는 그 단계의 보조 안내를 다시 시작한다 (`ChestSpot` 이후는 상자 안내, 대시 구역 이전은 대시 안내).

### C2. 문서
- `Docs/quests/CS_TUTORIAL.md`: §3-4 팝업 문구("지금 쏘세요!" → 실제 문구), §3-5(상자 안내가 보조 안내로 바뀐 점), §3-3(샷건 줍기 안내가 생긴 점), §9의 "아드레날린 비울지 정해야 한다"(이미 비움)를 갱신한다.
- `Docs/cutscene-debugger-state-plan.md`에 보충안 반영 사항을 덧붙인다.

### C3. 검증
- 상자를 안 열고 지나가기, 상자를 열고 비우지 않고 지나가기, 대시 안 쓰고 팔각방 진입, 구역을 달려서 통과하기를 각각 확인한다.
- 디버거로 임의 컷씬 → 이어서 진행 → 보조 안내가 이어지는지 확인한다.
- B단계 항목은 사람이 눈과 귀로 확인한다(문 개방, 시선, 레터박스, 효과음).
- 입력은 코드로 흉내 낸 확인이 가능하지만, 최종 확인은 실제 키보드 · 마우스로 한다.

## 5. 결정이 필요한 질문

1. 튜토리얼이 끝난 뒤 불러올 씬 이름은 무엇인가? (쉘터 프롤로그 씬이 Build Settings에 들어가는 시점)
2. 튜토리얼 BGM이 필요한가? 필요하면 컷씬 감독과 별도로 BGM을 이어 갈 오디오 원본을 새로 두는 것을 허용하는가?
3. B1에서 `TutorialMapScene`에 마커와 신호를 추가해도 되는가? 씬 파일에 이미 커밋하지 않은 큰 변경(약 3,400줄)이 있으니 먼저 커밋하거나 따로 보관한 뒤 진행하는 편이 안전하다.
4. 대시 안내(A4)를 필수에서 보조로 바꾸는 것이 의도와 맞는가? (대본 §3-2 문장과는 일치함)

## 6. 범위 밖 · 위험

- 적 경보 말풍선과 보라 방 적의 실행 중 모드 변경은 적 코드 수정이 필요해 제외한다.
- 문 · 잔해 · 샷건 스프라이트와 음원은 임시이며 이번에 교체하지 않는다.
- 사격 정지 시점(B2)은 실제 거리와 사거리 값을 확인해야 정해져 구현 중 방향이 바뀔 수 있다.
- 이 계획의 코드 변경은 모두 `_Sandbox` 안에서 끝난다.
